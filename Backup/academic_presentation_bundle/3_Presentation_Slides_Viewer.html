The Core Problem: Why Extensions Are Dangerous

Extensions run as highly privileged guest applications capable of observing cookies, injecting scripts, and hijacking web requests.

❌ Why Dynamic Sandboxes Fail at Scale

  • Prohibitive Latency: Running extensions in Puppeteer/Selenium takes 30–120 seconds per sample.
  • Evasion Tactics: Attackers use sleep timers, banking domain triggers, and detect navigator.webdriver to conceal malware.
  • Operational Danger: Executing hostile JavaScript creates container escape and resource exhaustion liabilities.

✅ Sentinel's Zero-Execution Solution

  • Sub-Millisecond Speed: Feature extraction takes 0.166 ms per extension.
  • 100% Safe: Analyzes packages strictly as static text streams; JavaScript is never executed.
  • Evasion-Resistant: Sleep timers and dormancy do not hide code signatures from static AST/regex scanners.

The Benchmark Paper (Wang et al., IEEE TIFS)

The gold-standard academic baseline for machine-learning-based browser extension detection.

📄 Benchmark Publication Overview

Paper: "Detecting Malicious Browser Extensions via Multi-View Static and Dynamic Analysis"

Venue: IEEE Transactions on Information Forensics and Security (TIFS)

Dataset: 4,677 extensions (3,187 benign, 1,490 malicious)

Sentinel's Core Strengths & Innovations

The four architectural pillars that make Sentinel powerful and unique:

1. 60-Feature Multi-Group Schema

Combines Manifest permissions (Group A), 27 JS static API calls (Group B), Obfuscation vs Minification heuristics (Group C), and behavioral combination flags (Group D).

2. 4-Tier Security Verdict Hierarchy

Replaces crude binary outputs with actionable tiers: KNOWN_MALICIOUS_IOC (1.0), HIGH_RISK (≥0.65), SUSPICIOUS_UNCERTAIN (0.20–0.64), and LOW_RISK (<0.20).

3. 100% Threat Recall Under Obfuscation

Even when attackers attempt to hide code behind commercial packers (Obfuscator.io), Sentinel maintains 100% detection recall, enforcing Chrome Web Store anti-obfuscation policies.

4. Production Web App with Audit Trail

Full-stack dashboard with real-time drag-and-drop inspection, live model probability calibration, and persistent SQLite history tracking.

What Should Be Improved in Sentinel (Future Roadmap)

Demonstrating academic maturity by identifying constructive engineering enhancements:

1. Expanding the Benign Dataset Scale

Current: 1,301 provenance samples and 260 balanced evaluation records.
Improvement: Ingest 2,000+ live verified Chrome Store extensions to further audit low-prevalence false alarms in the wild.

2. AST Constant Folding & De-Obfuscation

Current: Regex pattern matching and Shannon entropy.
Improvement: Integrate lightweight AST parsers (Babel/Esprima) with constant folding to automatically unpack string arrays and resolve dynamic URLs.

3. Hybrid Sandboxing for Uncertain Grayware

Current: Pure static scoring.
Improvement: Extensions in the SUSPICIOUS_UNCERTAIN (0.20–0.64) tier can trigger an automated 30-second headless browser network capture as a fallback.

4. Manifest V3 DeclarativeNetRequest Parsing

Current: Scans rules JSON.
Improvement: Deeper semantic analysis of declarative net request redirect targets to flag ad-injection before it happens.
